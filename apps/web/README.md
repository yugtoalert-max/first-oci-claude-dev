# apps/web

メモ API を使う簡易フロントエンドです(Vite + TypeScript、フレームワークなし)。仕様は [SPEC.md](../../SPEC.md) の 10 章です。

## 構成

| 場所 | 内容 | 自動テスト |
|---|---|---|
| `src/api/` | API クライアント層(fetch を包む) | あり |
| `src/ui/` | 画面から切り出した純粋なロジック(ルート、入力の上限、Retry-After、文言、トークンの保管) | あり |
| `src/screens/`、`src/app.ts` | DOM を操作する画面 | なし(下の手動確認) |
| `scripts/` | 配置スクリプト(`deploy:web` / `clean:web`)と手元の API サーバー | 純粋なロジックだけあり |

## 手元の開発サーバーで動かす

### 手元の API サーバーを使う(OCI に接続しない)

memo-api のアダプター(`createHandler`)にインメモリのリポジトリをつないだサーバーを、開発サーバーの `/api` の中継先にします。データはサーバーを止めると消えます。

```sh
npm install
cp apps/web/.env.example apps/web/.env
# apps/web/.env を VITE_API_BASE_URL=/api にする

npm run dev:api -w @memo/web   # 端末 1: http://127.0.0.1:8787/api
npm run dev -w @memo/web       # 端末 2: http://localhost:5173/
```

- トークンは `local-dev-token` です(`LOCAL_API_TOKEN` で変えられます)。違うトークンでは `401` になります
- ポートを変えるときは、両方の端末で `LOCAL_API_PORT=<ポート>` を渡します
- `429` を試すときは、次の N 回のリポジトリの操作をスロットリングにします: `curl -X POST 'http://127.0.0.1:8787/__local/throttle?count=1'`(`Retry-After` は API と同じ 1 秒)

### stg の API を使う

`apps/web/.env` を `VITE_API_BASE_URL=https://<API Gateway のホスト名>/api` にして `npm run dev -w @memo/web` を実行します。stg の `cors_allowed_origins` に `http://localhost:5173` が入っている必要があります(SPEC 8 章)。

## 手動確認のチェックリスト

UI は自動テストしないので、変更したらこの一覧で確かめます(SPEC 10.4)。手元の API サーバーでも stg でも同じ手順です。

### トークン

- [ ] 新しいタブで開くと、トークンの入力画面が出る
- [ ] 空のまま「使う」を押すと「トークンを入力してください」が出る
- [ ] 正しいトークンを入れると一覧が出る。再読み込みしても入力画面は出ない(sessionStorage)
- [ ] 間違ったトークンを入れると、入力画面に戻り、入れ直すよう案内が出る(`401`)
- [ ] 編集中に開発者ツールで sessionStorage の `memo.token` を書き換えて保存すると、入力画面に切り替わる。正しいトークンを入れると、入力中の内容が残った編集画面に戻り、もう一度保存できる
- [ ] `dist/` の JS にトークンの値が含まれていない(`grep -r <トークン> apps/web/dist` で何も出ない)

### 一覧

- [ ] 新しい順に並ぶ
- [ ] 21 件以上あるとき「もっと見る」が出て、押すと続きが下に追加される。最後まで読むとボタンが消える
- [ ] 20 件以下ならボタンは出ない。0 件なら「メモはまだありません」が出る
- [ ] タイトルに `<img src=x onerror=alert(1)>` を入れたメモが、そのままの文字列で表示される(一覧・編集画面とも。アラートが出ない)

### 新規作成

- [ ] 「新規作成」から作成すると、そのメモの詳細画面に移る。戻るボタンで空の作成画面に戻らない
- [ ] タイトルが空・空白だけのとき、エラーが出て「作成」を押せない
- [ ] タイトルが 200 文字(絵文字も 1 文字)を超えるとエラーが出る
- [ ] 本文の残りバイト数が表示され、日本語は 1 文字 3 バイトずつ減る。16,384 バイトを超えると赤字の「超えています」になり、作成できない

### 詳細 / 編集

- [ ] 一覧のタイトルから開くと、タイトル・本文・作成日時・更新日時が出る
- [ ] 何も変えていないときは「保存」を押せない。変えると押せて、保存すると「保存しました」が出て更新日時が変わる
- [ ] 存在しない id(`#/memos/01ARZ3NDEKTSV4RRFFQ69G5FAV`)を開くと「メモが見つかりません」が出る。形式の違う id(`#/memos/abc`)は「ページが見つかりません」になる

### 412(他で更新された)

- [ ] 同じメモを 2 つのタブで開き、タブ A で保存したあと、タブ B で変更して保存すると「他で更新されています。最新を読み込みますか?」が出て、タブ B の入力内容は消えない
- [ ] 「入力内容をコピー」でタイトルと本文がクリップボードに入る
- [ ] 「最新を読み込む」でタブ A の内容に置き換わり、そのあと保存できる
- [ ] タブ B で削除した場合も、同じ案内が出る(削除されない)

### 429(混み合っている)

- [ ] 手元の API サーバーで `__local/throttle` を呼んでから保存すると「混み合っています」が出て、保存ボタンが「保存(あと N 秒)」になり、秒数が経つまで押せない。自動では再送されない
- [ ] 秒数が経つと押せるようになり、保存すると成功する

### 削除

- [ ] 「削除」で確認ダイアログが出る。キャンセルすると何も起きない
- [ ] OK で削除され、一覧に戻る。一覧から消えている
- [ ] 未保存の変更があるときは、確認の文言に「保存していない変更も失われます」が入る

### 未保存のまま離れる

- [ ] 編集中(未保存)に「← 一覧へ」を押すと確認が出る。キャンセルすると留まり、URL も元のまま。OK で移る
- [ ] 編集中にブラウザの戻るボタンを押しても同じ確認が出る
- [ ] 編集中にタブを閉じる・再読み込みすると、ブラウザの確認が出る
- [ ] 保存したあとや、何も変えていないときは確認が出ない

## 配置(人が実行する)

`apps/web/dist` を Object Storage のバケットと同期します(SPEC 10.6)。**`npm run deploy:web` と `npm run clean:web` は人が実行します。Claude Code は実行しません。**

```sh
cp .env.example .env    # リポジトリのルート。namespace・バケット名・プロファイル・リージョンを入れる(Git 管理外)

npm run deploy:web -- --dry-run   # 実行されるはずの oci コマンドを表示するだけ(OCI には接続しない)
npm run deploy:web                # ビルドしてから同期する
npm run clean:web                 # バケットを空にする(terraform destroy の前に。OCI CLI が確認を求める)
```

- `deploy:web` の順序: バケットの一覧を取得 → `assets/*` → その他のファイル → `index.html` → dist/ にないオブジェクトを削除
- Content-Type は拡張子から付けます。知らない拡張子のファイルがあると、アップロードを始める前に止まります(`scripts/deploy-plan.ts` の `CONTENT_TYPES` に足します)
- Cache-Control: `index.html` とハッシュなしのファイルは `no-cache`、`assets/*` は `public, max-age=31536000, immutable`
- prod など別の配置先は `.env.prod` などに書き、`--env-file .env.prod` で渡します
- スクリプトは `node` で TypeScript を直接実行します(型を取り除く機能を使うので、Node.js 22.18 以降)
